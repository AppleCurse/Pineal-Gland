# RISK REGISTER

| ID | File/Module | Function | Risk/Gap | Evidence | Impact | Recommended Fix | Severity |
|----|-------------|----------|----------|----------|--------|-----------------|----------|
| R-001 | `orchestrator.py` | `run_pipeline` | Unhandled Coroutine in list | `record["steps"].append(step)` where `step` is an awaited task or unawaited coroutine causing type errors (`TypeError: 'coroutine' object is not subscriptable`). | Pipeline crashes on task creation, returning 500 equivalent errors in background loops. | Await `self._step` before appending it to `record["steps"]`. | CRITICAL |
| R-002 | `services/session_store.py` | `_derive_key` | Unhandled empty hex string | `SESSION_STORE_KEY` crashes if it is exactly empty string or non-hex string, despite memory requirements saying it should disable gracefully. | Startup failure for `agent_core`. | Wrap `bytes.fromhex` in a try/except and set `self.disabled = True` if it fails. | HIGH |
| R-003 | `orchestrator.py` | `build_default_services` | Hardcoded tight coupling | Imports like `AgentZeroClient`, `ElizaClient` are directly instantiated inside the orchestrator rather than using a true Registry pattern. | Refactoring and adding new agents requires core modification instead of configuration. | Implement a `CapabilityRegistry` abstraction for loading agents. | MEDIUM |
| R-004 | Configuration | Multiple `.env` scopes | `.env.example` in root, `.env.example` in `agent_core`, CLI args in `start_all.ps1`. | Keys are duplicated across files (e.g. `LITELLM_MASTER_KEY`). | Risk of configuration drift; starting via script works, running manually fails. | Centralize configuration or clearly delineate backend vs frontend config boundaries. | LOW |
| R-005 | `services/uitars.py` | Remote Config | Bypass LLM Gateway | `UITARS_REMOTE_ENDPOINT` makes a direct network call bypassing the LiteLLM proxy and its circuit breaker/budgeting. | Blind spot in token tracking and API health management. | Route VLM calls through LiteLLM proxy if LiteLLM supports VLM, or establish a dedicated VLM Circuit Breaker. | LOW |
| R-006 | Security | General | Unvalidated Execution | `agent_core` allows unvalidated intentions to be passed to shell via LocalSandboxProvider in DeerFlow. | Potential arbitrary code execution on the host machine. | Implement strict schema validation and sandboxing for the intention prompt, ensuring DeerFlow runs in a containerized sandbox. | HIGH |
